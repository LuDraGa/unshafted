## Round 2 — adversarial sweep findings (2026-05-07)

Goal: find anything else a Purple Nickel reviewer could cite after the disclosure pass landed.

### Must-fix → fixed

1. **Orphan content script package.** `pages/content/` was a registered workspace package whose build emitted `dist/content/all.iife.js` — a 60KB script that scrapes arbitrary web pages. It was unwired (not in `manifest.json` `content_scripts`, no importer in popup/options/background) but Turbo built it anyway, so the ZIP shipped a page-scraping script alongside a manifest that claims `permissions: ['storage', 'identity']` only. That's the cleanest possible "single-purpose drift + permissions inconsistency" citation. Fix:
   - Deleted `pages/content/`
   - Deleted `packages/shared/lib/utils/unshafted-browser.ts` (the `chrome.scripting.executeScript` helper that called into the now-removed message handler) and dropped the re-export from `packages/shared/lib/utils/index.ts`
   - Removed the dead `pages/content` and (already-nonexistent) `pages/side-panel` entries from `pnpm-workspace.yaml`
   - Removed `EXTRACT_PAGE_MESSAGE_TYPE`, `ExtractPageRequest`, and `ExtractPageResponse` from `packages/unshafted-core/lib/runtime.ts` since their only consumers were the deleted files

2. **Email PII in service-worker console.** `chrome-extension/src/background/index.ts:18` logged `session.user.email` on every auth state change. Not transmitted but visible to anyone who opens the service-worker DevTools. Stripped to `console.info('[Unshafted] auth state:', event)`.

### Should-fix → fixed

3. **Consent modal didn't mention the Supabase profile row.** Modal listed Google email/profile, Supabase session token, Drive token; policy §2 also says the Drive backup preference is written to a Supabase profile row. Added a bullet to the modal in `pages/popup/src/Popup.tsx`.

4. **Two storage keys not enumerated in the policy.** `unshafted-drive-folder-id` (Drive folder-ID cache, `packages/supabase/lib/drive.ts`) and the SHA-256 `testedKeyHash` inside the onboarding state (`packages/unshafted-core/lib/schemas.ts`) were inside categories the policy already covered but never named. Expanded `cws/privacy-policy.md` §2 to enumerate them, plus the new `privacyConsentAcceptedAt` field added in this version. Bumped effective date to 2026-05-07.

### Cleared

- Network egress (only Supabase, googleapis, openrouter.ai, api.openai.com)
- Analytics / telemetry / Sentry — none in deps or source
- Remote code — no eval/Function/CDN/Google Fonts
- OAuth scopes — exactly `openid email profile drive.file`
- `drive.file` queries — all folder-scoped
- All other `console.log` lines log generic error objects, not PII or tokens

## Why this should clear Purple Nickel

CWS Purple Nickel rejections cite a privacy policy "missing necessary information," but the actual review surface is the union of **policy + in-product disclosures + listing copy**. The old listing told users their data stayed on their device while the policy described Supabase + Drive — so any disclosure that lived only in the policy looked partial relative to the listing's broader claim. The new state has consistent claims across all three surfaces and a pre-collection disclosure screen the reviewer can step through, which is what the Chrome troubleshooting doc literally asks for.
